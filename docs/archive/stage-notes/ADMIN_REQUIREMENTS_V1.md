# 관리자 페이지 요구사항 V1

이 문서는 PostgreSQL DB 설계와 FastAPI 백엔드 설계의 기준 문서입니다.  
관리자 페이지는 단순 조회 화면이 아니라, **게임 밸런스와 운영값을 코드 수정 없이 바꾸는 운영 도구**입니다.

## 1. 핵심 원칙

```txt
게임 밸런스 값은 코드가 아니라 DB에 둔다.
관리자 페이지는 DB 값을 수정한다.
FastAPI는 수정값을 검증하고 변경 이력을 남긴다.
```

## 2. 캐릭터 확장 원칙

앞으로 캐릭터가 추가됩니다.

```txt
캐릭터마다 다른 것: 스킬
공통으로 쓰는 것: 아이템, 장비, 보스, 드랍, 강화, 필드, 인벤토리, 재화
```

따라서 DB도 아래처럼 설계합니다.

```txt
공통 마스터 데이터:
items, bosses, drop_tables, field_zones, enhancement_rules

캐릭터별 마스터 데이터:
characters, skills, character_skills, skill_levels
```

### 아이템 관리

관리자가 수정할 수 있어야 하는 값:


```txt

```

## 5. 필수 안전장치

관리자 자유도가 높기 때문에 아래 기능은 필수입니다.

```txt
수정 전 값 저장
수정 후 값 저장
수정 관리자 저장
수정 시각 저장
수정 사유 저장
미리보기/검증 후 적용
되돌리기용 rollback 데이터 저장
권한 체크
운영 기능과 개발 테스트 기능 분리
```

## 6. 권한 초안

```txt
super_admin: 모든 메뉴 접근
balance_admin: 아이템/보스/드랍/강화/필드/스킬 수정
content_admin: 캐릭터/이벤트/우편 수정
support_admin: 유저 조회/우편 지급
viewer: 조회만 가능
```

## 7. V1에서 아직 하지 않는 것

```txt
관리자 화면 디자인 완성
복잡한 승인 워크플로우
실시간 통계 대시보드
자동 밸런스 시뮬레이터
```

이 문서는 V1 기준이며, 실제 운영 전에 권한/검증/되돌리기 정책은 더 강화해야 합니다.
